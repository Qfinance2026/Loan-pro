# MongolLoan Cloud Demo V1.0

**Туршилтын систем. Бодит санхүүгийн үйлдвэрлэлийн ашиглалтад тохируулаагүй.**

## Боломжууд
- Admin / Operator / Viewer гэсэн 3 эрхтэй, нууц үг хадгалалт нь hash ашиглана.
- Зээлдэгч (иргэн, байгууллага), зээлийн бүртгэл; MNT, жилийн Actual/365.
- Аннуитет / тэнцүү үндсэн / эцэст үндсэн төлөх график; сар бүр.
- Нэмэгдүүлсэн жилийн хүүг зээл бүрээр тохируулж, хугацаа хэтэрсэн үндсэн дээр тооцно.
- Төлөлтийн хуваарилалт: нэмэгдүүлсэн хүү → үндсэн хүү → үндсэн зээл.
- Урьдчилсан төлөлтөд график хэвээр / төлбөр бууруулах / хугацаа богиносгох.
- Зээл тус бүрийн төлөлтийн түүх, барьцааны мэдээлэл, зээлийн багцын Excel тайлан, Excel импорт, аудит.

## 0 ₮ орчин: Render + Supabase
1. https://supabase.com дээр **Free** project үүсгээд Database password-аа аюулгүй хадгал.
2. Supabase **Connect → Session pooler**-ийн connection string-ийг хуулж ав. Shared pooler 5432 нь IPv4 дэмждэг; `?sslmode=require` параметртэй байна. Хэрэв 6543 transaction pooler ашиглавал драйверийн prepared statement-тай холбоотой тохиргоо шаардаж магадгүй. Session pooler илүү хялбар.
3. ZIP-ийг задлаад бүх файлыг **private GitHub repository**-д оруул. `.env` файлыг repository-д бүү оруул!
4. https://render.com → **New → Blueprint** (эсвэл New → Web Service) → GitHub private repository холбоод `render.yaml`-аа сонго. Үнэгүй Free plan-ыг баталгаажуул.
5. Render env vars: `DATABASE_URL` = Supabase connection string (password дотор `@`, `#`, `?` гэх мэт байвал URL encode хийх); `ADMIN_USERNAME` = таны сонгосон нэр; `ADMIN_PASSWORD` = 12+ тэмдэгтийн хүчтэй нууц үг; `SECRET_KEY` = Render автоматаар үүсгэнэ; `SESSION_COOKIE_SECURE` = `1` (Render дээр yaml дотроо нэмж тохируулж болно).
6. Deploy болсны дараа `https://...onrender.com/login` хаягаар нэвтэр. Эхний админ зөвхөн хоосон сан дээр автоматаар үүснэ. Admin → Хэрэглэгч цэсээр шинэ хэрэглэгч нэмнэ.
7. Хэрэв анхны username/password-ыг тохируулахаас өмнө хоосон сан үүссэн бол env vars-ийг тохируулаад Render redeploy хийнэ.

**АНХААР:** Supabase database password, ADMIN_PASSWORD, SECRET_KEY-г чатаар болон GitHub-д илгээж болохгүй. Утсаар ч холбогдож болно.

## Локал туршилт
```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
# local .env файлд ADMIN_USERNAME, ADMIN_PASSWORD, SECRET_KEY тохируулах
python app.py
```
SQLite-г зөвхөн local хөгжүүлэлтэд ашиглана. Render Free дээр SQLite хадгалахгүй: restart/redeploy үед өгөгдөл алдагдана.

## Ограничения / Хязгаарлалт
- **Зөвхөн Demo**: бодит зээл, регистр, гэрээний хавсралт бүү байршуул.
- Энэ хувилбар **гэрээний хавсралт upload, rollback/void payment, backup/restore, бүрэн transaction/day-end reconciliation**-гүй. Өөрчлөлтийн аудит хязгаарлагдмал.
- График шинэчлэх нь туршилтын логик. Өмнөх товлогдсон төлөлт, нөхөн төлөлттэй бүх нөхцөлийг хангаж чадахгүй; тусгай test-case-ээр баталгаажуулах шаардлагатай.
- Төлбөрийн хүү өдөр бүр cent-тэй адил 0.01 төгрөгөөр дугуйлагдсан хэсгүүдийн нийлбэр; төлбөр бүрийн огноогоор хүү дахин тооцно.
- Өмнөх огноогоор төлөлт бүртгэхийг хязгаарласан боловч түүхэн графикийн дахин тооцоолол болон барьцааны хууль эрх зүйн процесс нэмэлт хөгжүүлэлт шаарддаг.
- Login brute-force хамгаалалт, MFA, захиалгат эрхийн бодлого, audit integrity хамгаалалт, нууцлалын эрх зүйн аудит, backup/restore автоматжуулалтгүй.
- Энэ код `create_all()` ашиглана; production upgrade-д Alembic migrations ашиглах ёстой.
- Render Free 15 минут идэвхгүй байвал унтарна; дараагийн хүсэлтэд асах хугацаа орно. Supabase Free хязгаарлалтыг албан сайтаас шалга.

## Шалгах сценари
1. Admin нэвтэрч Operator болон Viewer нэмэх.
2. Operator зээлдэгч, 100,000,000₮ 24% 12 сар зээл нэмэх.
3. Viewer зөвхөн тайлан болон зээлийг харах, POST үйлдэл хийх эрхгүй эсэх.
4. Төлөлт оруулах, үлдэгдлийн өөрчлөлт, график шинэчлэлт, Excel экспорт шалгах.
5. Excel importer-д duplicate гэрээ өгч rollback болж байгаа эсэх.

Эхний ашиглалтад зохиомол мэдээлэл ашигла. Санхүүгийн системийн бүх тооцоолол байгууллагын аргачлал, гэрээ, холбогдох зохицуулалттай баталгаажуулах ёстой.
